# 第二期开发计划

更新：2026-10-06。M1、M2、M3 本轮范围已完成，核心已更新至 `bff3e8a`，执行器保持 `1990d16`；Jev 按用户要求暂保留。

目标是用可复现实验衡量诊断能力，再依据证据改进规划、总结与路由。分为三个可验收里程碑，不把单步评测分数描述成完整 Agent 效果。

| 里程碑 | 内容 | 验收证据 |
| --- | --- | --- |
| M1：建立基线（已完成） | 60 条版本化路由／单步规划案例、40/20 分组、hybrid/model 对照、确定性评分、次数与时间上限、费用未知规则、失败报告与 CI | 200 个真实模型评测样本、168 次请求、原始失败与逐项复核；多目标请求防护及离线回归，见基线报告 |
| M2：完整诊断与故障夹具（已完成） | 可复位的隔离故障场景；共用生产诊断循环的完整轨迹回放；结构化假设、证据、验证及不确定性；PostgreSQL 实验归档 | 3 种真实 Docker 故障采集、8 个控制回放、22 次模型请求的两轮报告；独立 PG 8 次运行／222 样本及备份恢复验证 |
| M3：路由对照与发布（已完成，Jev 延期） | 新场景下 hybrid/model 重复对照、诊断回归、镜像与数据库回滚准备、部署验收；Jev 暂保留 | 18 条路由两方案各重复两次，6 条诊断重复两次；90 项测试、真实部署与隔离测试容器验收、PG 备份恢复 |

M1 实测与限制见 [基线报告](phase2-baseline.md)。当前本地完整检查为 99 项测试（含真实隔离 PostgreSQL），Ruff 检查和格式检查通过。M2 验收见 [完整诊断报告](phase2-diagnosis.md)；M3 结果及诊断限制见 [发布报告](phase2-release.md)。10 月 6 日追加的[诊断修复验收](diagnosis-followthrough.md)采用已知回归集和新评分版本，保留 5/6 的原始结果，不能与旧分数直接比较。M2 不在个人业务容器制造故障；M3 未配置或未运行的方案记为未测，不生成虚构分数。是否引入 Jev 运行依赖由实际结果决定。

数据集和执行说明见 [评测目录](../evals/README.md)。线上当前核心为 `bff3e8a`、执行器为 `1990d16`，M1 评测程序独立运行，无 Docker 执行、企微发送或数据库写权限。

M2 已落实结构化引用校验、程序生成停止原因与工具能力说明、共用诊断循环回放、独立 PostgreSQL 归档。它不保证模型自然语言语义正确。M3 已完成新案例和 hybrid/model 对照，保留原始失败评分。按用户反馈，Jev 注册暂停，因此保留 IntentRouter 接口接入点，不添加运行依赖、不发送请求、不生成 Jev 分数；注册恢复后再评估。已分析案例仅作为已知回归集，不作为新的泛化证据。
