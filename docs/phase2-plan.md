# 第二期开发计划

更新：2026-10-04。用户已授权开始第二期，第一期线上运行版本保持不变。

目标是用可复现实验衡量诊断能力，再依据证据改进规划、总结与路由。分为三个可验收里程碑，不把单步评测分数描述成完整 Agent 效果。

| 里程碑 | 内容 | 验收证据 |
| --- | --- | --- |
| M1：建立基线 | 60 条版本化路由／单步规划案例、40/20 分组、hybrid/model 对照、确定性评分、次数与时间上限、费用未知规则、失败报告与 CI | 评测器测试、规则覆盖报告、真实 DeepSeek 运行与失败分析 |
| M2：完整诊断与故障夹具 | 可复位的隔离故障场景；共用生产诊断循环的完整轨迹回放；结构化假设、证据、验证及不确定性；PostgreSQL 实验归档 | 容器退出、依赖不可用、配置错误场景；预算、重复检查、错误恢复及证据约束；优化前后报告 |
| M3：路由对照与发布 | 在基线基础上接入 Jev 适配进行对照；重复运行、错误类别、延迟和费用分析；选择是否启用 | 相同案例的对照实验、明确限制、第二期演示与部署记录 |

当前先完成 M1。M2 不在个人业务容器制造故障；M3 未配置或未运行的方案记为未测，不生成虚构分数。是否引入 Jev 运行依赖由实际结果决定。

数据集和执行说明见 [评测目录](../evals/README.md)。线上当前仍为第一期已验收的代码，M1 评测程序独立运行，无 Docker 执行、企微发送或数据库写权限。
