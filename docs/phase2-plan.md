# 第二期开发计划

更新：2026-10-05。M1、M2 已完成，第一期线上运行版本保持不变。

目标是用可复现实验衡量诊断能力，再依据证据改进规划、总结与路由。分为三个可验收里程碑，不把单步评测分数描述成完整 Agent 效果。

| 里程碑 | 内容 | 验收证据 |
| --- | --- | --- |
| M1：建立基线（已完成） | 60 条版本化路由／单步规划案例、40/20 分组、hybrid/model 对照、确定性评分、次数与时间上限、费用未知规则、失败报告与 CI | 200 个真实模型评测样本、168 次请求、原始失败与逐项复核；多目标请求防护及离线回归，见基线报告 |
| M2：完整诊断与故障夹具（已完成） | 可复位的隔离故障场景；共用生产诊断循环的完整轨迹回放；结构化假设、证据、验证及不确定性；PostgreSQL 实验归档 | 3 种真实 Docker 故障采集、8 个控制回放、22 次模型请求的两轮报告；独立 PG 8 次运行／222 样本及备份恢复验证 |
| M3：路由对照与发布 | 在基线基础上接入 Jev 适配进行对照；重复运行、错误类别、延迟和费用分析；选择是否启用 | 相同案例的对照实验、明确限制、第二期演示与部署记录 |

M1 实测与限制见 [基线报告](phase2-baseline.md)。当前本地完整检查为 89 项测试（含真实隔离 PostgreSQL），Ruff 检查和格式检查通过；没有为结果更好看而重跑保留集。M2 验收见 [完整诊断报告](phase2-diagnosis.md)；M3 尚未完成。M2 不在个人业务容器制造故障；M3 未配置或未运行的方案记为未测，不生成虚构分数。是否引入 Jev 运行依赖由实际结果决定。

数据集和执行说明见 [评测目录](../evals/README.md)。线上当前仍为第一期已验收的代码，M1 评测程序独立运行，无 Docker 执行、企微发送或数据库写权限。

M2 已落实结构化引用校验、程序生成停止原因与工具能力说明、共用诊断循环回放、独立 PostgreSQL 归档。它不保证模型自然语言语义正确。下一步 M3 再加入新案例、独立复核和可选 Jev 路由对照；是否部署和启用新路由取决于实测。已分析案例仅作为已知回归集，不作为新的泛化证据。
