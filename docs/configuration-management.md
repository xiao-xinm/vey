# 服务配置管理、版本审计与回滚

本阶段将服务登记迁入执行器管理的版本表，后台提供编辑、校验、差异确认和回滚草稿。范围为已有 Compose 服务的 key、别名、保护标志和健康检查 URL；不提供容器部署、任意命令、密钥编辑或操作确认入口。

## 使用

登录后台，打开“服务配置”。修改或添加登记，填写原因，点击“校验并查看差异”；核对新增／删除／修改内容、服务顺序及缺失容器提示，勾选确认后发布。每次操作最多 50 个服务、每服务 8 个别名，请求最多 64 KiB。新增项必须匹配真实 Compose 项目／服务标签，已有历史登记项未匹配时保留并警告，不假装它已部署。

健康检查允许 HTTP(S)，不允许凭据、查询参数、URL 片段及无效端口；保存或校验不会访问该 URL。真正健康检查仍只由固定查询工具执行。健康地址和别名会保存在配置历史中，请勿填入秘密信息。

校验结果有效 5 分钟，绑定当前版本、完整候选内容、原因、回滚来源和容器 ID。编辑、过期、并发发布或容器替换都会使原校验无效。退出登录清除本地草稿与待发布凭据；异步返回不能重新激活旧草稿。发布失败或响应丢失时先刷新核对生效版本，不自动重试。

历史区展示最近 100 个版本（数据库保留完整历史）；回滚先载入历史服务列表，再经过同样的校验与确认。回滚产生新版本，保留原始版本及原因，不倒退版本 ID。相同内容不重复发布。

## 安全与并发

- `config/vey.toml` 仍为 root 维护的只读保护基线。owner、自身项目、保护项目、固定容器 ID、阈值均不开放编辑；基线内受保护服务和自身项目登记项不能删除或解除保护。后台可为其他服务增加保护；基线以外的可编辑标志可以调整。
- 基线哈希保存在状态表中。手工改文件后与已初始化状态不一致会拒绝使用配置；基线扩充由管理员另行评审及迁移。
- 后台数据库账号仍为只读。配置写入通过执行器 Unix socket 的独立管理令牌进行，只开放读取配置、校验、发布三个接口。管理令牌不能调用运维接口，核心的运维令牌不能调用管理接口；浏览器拿不到服务间令牌。
- 核心在每个新任务开始取得当前策略快照；读取和准备修改均携带版本。若模型等待期间版本变化，执行器拒绝旧请求，用户需重新发起。固定基线身份不变，已有操作确认仍须在企微完成。
- 每次发布／回滚原子地插入版本、切换生效指针、取消全部 pending 确认。确认哈希含版本 ID，因此内容回滚也不能恢复旧授权。旧会话仍保留 15 分钟期限，旧游标是否可用还受当前服务配置检查。
- 查询／准备／确认使用 PostgreSQL 事务级共享咨询锁；发布使用同一个键的排他锁，确认持锁直到 Docker 调用及结果持久化结束。等待锁超过 5 秒则发布失败，不绕过锁。配置锁使用独立连接池，避免占满操作写入连接造成互相等待。[PostgreSQL 咨询锁](https://www.postgresql.org/docs/16/functions-admin.html#FUNCTIONS-ADVISORY-LOCKS)
- executing 或 unknown 操作存在时拒绝发布；先按现有人工核对流程处理。配置发布不替用户清除未知锁，也不能撤销已经发生的 Docker 操作。
- 版本表拒绝 UPDATE／DELETE，并撤销运行角色的 UPDATE／DELETE／TRUNCATE 权限；记录父版本、服务内容、原因、时间和回滚来源。成功发布就是持久审计，拒绝的请求不生成版本。当前为单一后台管理员，不声称能区分多个自然人，也不声称抵抗数据库管理员或执行器整体失陷。

## 部署

先备份并演练恢复，确认无活动任务／操作，保存旧核心、执行器、后台镜像和 `.env`。短暂停止核心与执行器，使用迁移所有者执行 `alembic upgrade head`（新增 `0003`）；运行角色不能自行建表。迁移只新增 `vey_exec.policy_versions`、`policy_state` 和历史防改触发器，保留原有数据。

管理员生成独立随机 `secrets/configuration_token`（root:10000 / 0640），不要复制运维令牌。保持目录仅管理员可写。在现有 `COMPOSE_FILE` 最后追加 `compose.configuration.yaml`，设置 `VEY_CONFIGURATION_IMAGE=vey-agent:<冻结发布版本>`，保留已有所有叠加项。

```bash
docker compose up -d --no-deps --force-recreate --wait ops-executor
docker compose up -d --no-deps --force-recreate --wait agent-core dashboard
```

执行器首次启动从文件基线初始化一个版本；以后从数据库读取，发布无需重启。后台仅新增只读 runtime 目录挂载及配置管理令牌，不挂载 Docker socket，也不持有管理员数据库连接。核心／执行器需同时升级，旧客户端未传版本时会拒绝读取／准备请求。

代码回退前停止核心与执行器，核对最新配置与基线差异，暂停配置入口；不能直接启动只懂文件配置的旧执行器并忽略已发布的新保护规则。若需要旧版本运行，先由管理员把经审核的有效服务配置合入只读文件并重建容器，再恢复服务；配置历史表保留，不 downgrade、不倒灌旧数据库。备份恢复应同时覆盖数据库和匹配的文件基线。

自动化验证包括真实 PG 版本迁移、保护约束、预览篡改／过期／容器替换、旧确认与回滚、未知操作阻断、并发锁、管理令牌隔离、CSRF、体积限制、前端草稿失效。真实浏览器点击／布局验收受当前 CUA 超时影响，不能用接口检查替代。
