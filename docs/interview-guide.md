# Vey 求职讲解材料

适用于 AI 应用／Agent 开发方向。所有数字指本项目已记录的实验，不是线上 SLA；个人经历和独立贡献范围请按本人实际情况表述。架构配图见[项目结构指南](project-map.md)。

## 60 秒介绍稿

> Vey 是一个通过企业微信管理个人 Ubuntu 服务器的运维 Agent。我把系统分成消息核心、受控执行器和管理后台：核心负责理解请求、规划只读诊断和组织结果，执行器独立检查权限并调用固定 Docker API。启停操作需要两分钟内的二次确认，数据库和 Agent 自身等服务受保护；诊断最多五步、六十秒，日志和模型输出都不能直接变成命令。
>
> 我用 PostgreSQL 保存任务、审计、确认状态和评测记录，做了配置版本及回滚、离线复核、本机备份与隔离恢复。发布版本有 147 项自动测试；评测库保留 16 次实验和 420 条样本，包括失败。也接入并比较过 Jev：这组已知路由回归中，通过率没有增加，P95 从约 1.12 秒变成 3.74 秒，所以仍保留规则优先加 DeepSeek 的默认方案。

## 面试追问与回答依据

| 追问 | 应该讲清楚什么 | 代码／证据 |
| --- | --- | --- |
| 为什么叫 Agent，而不是聊天接口？ | 诊断会根据真实工具证据选择下一步，重复直到结论或停止条件；修改能力另行确认 | `diagnosis.py`、`core.py` |
| 为什么不用 Agent 框架？ | 当前流程和工具有限，显式控制流更便于观察预算、权限及恢复边界；不是框架一定不好 | `domain.py`、`diagnosis.py` |
| 怎么阻止提示注入？ | 日志仅是数据；工具集合、目标目录、执行器校验和保护规则独立于模型；不能承诺模型语义永不受影响 | `model.py`、`executor.py`、安全评测案例 |
| 模型判断重启就执行吗？ | 只准备确认记录；再次确认才消费 grant，而且重新校验会话、策略和容器身份 | `Executor.prepare / confirm` |
| Docker 权限怎么隔离？ | 核心与后台无 socket；执行器固定 API 和独立身份，但其 Docker 权限仍高，需要信任这个进程 | Compose、`executor_app.py` |
| 为什么不用 SQLite？ | 需要运行期独立角色、并发锁和审计；用户已有 PG，因此使用现有实例、专用库和角色 | `db.py`、migrations |
| PG 和 Docker 如何保证一致性？ | 无跨系统事务；先持久化 executing，发生不确定性时标 unknown、拒绝自动重放和后续冲突变更，再人工核对 | `executor.py`、`scripts/reconcile_operation.py` |
| 如何防重复消息？ | 平台消息编号唯一约束、确认状态和投递分段记录；外部平台与 PG 仍有重复投递窗口 | `Core.accept / send_pending` |
| 为什么配置回滚会作废旧确认？ | 确认绑定的是当时策略和容器；回滚也生成新版本，不能把旧授权复活 | `policy_registry.py` |
| 评测的 36/36 能证明什么？ | 18 个已知路由案例各两次的契约通过，不等于独立样本 36 个，也不是诊断正确率 | `docs/jev-live-evaluation.md` |
| 有失败样本吗？ | 诊断回归有 5/6 的保留结果；能力缺失与配置故障分类存在歧义，未改标签把它算成通过 | `docs/diagnosis-followthrough.md` |
| Jev 为什么默认关闭？ | 多数请求分类后仍需 DeepSeek 参数解析，增加串行请求；以原始报告说明取舍 | Jev 54 次 vs hybrid 28 次请求 |
| 备份过就能恢复吗？ | 还要验证数据、视图、角色权限，并隔离旧任务／确认，防止恢复后重放副作用 | `scripts/operations_drill.py` |

## 推荐的五分钟技术讲解顺序

1. 用结构图说明三个主要服务的权限，30 秒。
2. 沿“消息入队 → 规则／模型 → 固定工具 → 结果投递”解释一次查询，45 秒。
3. 展示确认记录和 unknown 边界，60 秒。
4. 展示带证据的诊断与失败案例，60 秒。
5. 展示 Jev 对照及为何默认关闭，45 秒。
6. 展示配置回滚、恢复报告和未完成边界，60 秒。

演示步骤、台词和实际录制检查表见[演示脚本](demo.md)。这份材料是准备好的讲稿，不表示已经录制视频。
